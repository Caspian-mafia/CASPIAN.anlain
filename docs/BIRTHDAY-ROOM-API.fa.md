# API اتاق تولد CASPIAN

ماژول اتاق تولد در سرور اصلی زیر مسیر `/api/birthday` نصب شده و REST آن به Bearer session معتبر نیاز دارد.

## مسیرهای HTTP
- `POST /rooms`: ساخت اتاق خصوصی. ورودی: `themeId`, `honoreeUserId` (UUID حساب), `layout` (circle/semicircle/staggered/two-sided), `guestCount` (۲ تا ۱۶). کسر ۲۰٬۰۰۰ سکه، ثبت ledger، اتاق، رویداد تولد و اعضای اولیه در یک تراکنش PostgreSQL انجام می‌شود.
- `GET /rooms`: اتاق‌هایی که حساب جاری عضو آن‌هاست.
- `GET /rooms/:id`: جزئیات و فهرست اعضا؛ فقط اعضا.
- `POST /rooms/:id/invites`: صدور دعوت‌نامه با انقضا و سقف استفاده. فقط hash ذخیره می‌شود و کد خام یک‌بار برگردانده می‌شود؛ صدور مجدد کد قبلی را باطل می‌کند.
- `POST /rooms/:id/join`: ورود مهمان با شناسه اتاق و کد دعوت؛ مهمان رایگان است و اتاق به وضعیت active می‌رود. ظرفیت مهمانان با `guestCount` تنظیم‌شده کنترل می‌شود؛ قفل ردیف اتاق در تراکنش از ورود هم‌زمان بیش از ظرفیت جلوگیری می‌کند.
- `POST /rooms/:id/gifts`: انتقال آواتور/قاب تحت مالکیت فرستنده به عضو دیگر اتاق.
- `GET /rooms/:id/gifts`: تاریخچه هدایا برای اعضا.
- `GET /rooms/:id/messages`: ۵۰ پیام اخیر برای اعضای اتاق.
- `POST /rooms/:id/close`: بستن اتاق، باطل‌کردن دعوت‌نامه‌ها و ارسال رویداد بسته‌شدن به Socket.IO.

## رویدادهای Socket.IO
- `birthday:join`: احراز نشست، کنترل عضویت در اتاق و عضویت در کانال خصوصی `birthday:<roomId>`.
- `birthday:presence`: فهرست نام مهمانان آنلاین همان اتاق.
- `birthday:chat:send`: ثبت پیام متنی حداکثر ۵۰۰ نویسه در PostgreSQL و پخش آن فقط برای اعضای آنلاین اتاق.
- `birthday:chat:message`: پیام ثبت‌شده.
- `birthday:leave`: خروج از کانال اتاق.
- `birthday:closed`: اطلاع‌رسانی بسته‌شدن اتاق.

## اجرای دیتابیس و مرزهای نسخه
- `persistence.js` در زمان راه‌اندازی سرور، فایل `database/social-guilds-birthdays.sql` را اجرا می‌کند؛ migrationها idempotent هستند.
- صفحه `/birthday-room.html` از `caspianAuthToken` حساب اصلی استفاده می‌کند و Socket.IO را از همان origin می‌گیرد. تعداد صندلی‌های نمایشی و الگوی چیدمان با انتخاب تعداد مهمان و نوع چیدمان به‌روزرسانی می‌شود.
- حضور و گفت‌وگوی متنی بلادرنگ پیاده‌سازی شده‌اند. تماس صوتی WebRTC، ویدئو، پرداخت هدیه با سکه و جداسازی کیف پول خریداری‌شده از سکه‌های پاداش هنوز پیاده‌سازی نشده‌اند.
- commit در GitHub به‌تنهایی به معنی انتشار روی سرور عمومی نیست. برای اجرای migration در محیط عملیاتی، سرور باید با `DATABASE_URL` معتبر راه‌اندازی/بازراه‌اندازی شود. در این محیط دسترسی به میزبان یا اعتبارنامه پایگاه‌داده عملیاتی فراهم نیست؛ بنابراین اجرای migration روی سرور زنده و آزمون end-to-end ادعا نمی‌شود.
