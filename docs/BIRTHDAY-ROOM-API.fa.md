# API اتاق تولد CASPIAN

این ماژول در سرور اصلی آنلاین و زیر مسیر `/api/birthday` قرار دارد. تمام مسیرها به Bearer session معتبر نیاز دارند.

## مسیرها
- `POST /rooms`: ساخت اتاق خصوصی. بدنه: `themeId`, `honoreeUserId` (UUID حساب), `layout` (circle/semicircle/staggered/two-sided), `guestCount` (۲ تا ۱۶). فقط صاحب اتاق ۲۰٬۰۰۰ سکه می‌پردازد؛ کسر کیف پول، ثبت ledger، اتاق و رویداد تولد در یک تراکنش PostgreSQL انجام می‌شود.
- `GET /rooms`: اتاق‌های تولدی که حساب جاری عضو آن‌هاست.
- `GET /rooms/:id`: جزئیات و فهرست اعضا؛ فقط اعضا.
- `POST /rooms/:id/invites`: صدور کد دعوت خصوصی با انقضا (پیش‌فرض ۷۲ ساعت) و سقف استفاده اختیاری. کد خام فقط یک بار به صاحب اتاق برگردانده می‌شود؛ فقط hash در DB ذخیره می‌شود و صدور کد جدید، کد فعال قبلی را باطل می‌کند.
- `POST /rooms/:id/join`: ورود مهمان با کد دعوت؛ مهمان هزینه ورود نمی‌پردازد.
- `POST /rooms/:id/gifts`: انتقال یک آواتور/قاب موجود در مالکیت فرستنده به عضو دیگر همان اتاق. آیتم از موجودی فرستنده حذف و به دارایی گیرنده اضافه می‌شود؛ هدیه رایگانِ سیستمی یا خرید خودکار انجام نمی‌شود.
- `GET /rooms/:id/gifts`: تاریخچه هدایا برای اعضا.
- `POST /rooms/:id/close`: بستن اتاق و باطل‌کردن دعوت‌نامه‌های فعال.

## نکات عملیاتی
- schema جدید از مسیر migration موجود `persistence.js` بارگذاری می‌شود.
- صفحه در `/birthday-room.html` از توکن حساب ذخیره‌شده توسط برنامه اصلی استفاده می‌کند.
- این نسخه مدیریت پایدار اتاق/اعضا/دعوت/هدیه را از طریق REST پیاده می‌کند؛ هنوز جلسه صوتی زنده، WebRTC، حضور بلادرنگ Socket.IO، پرداخت هدیه با سکه و آزمون end-to-end روی PostgreSQL مستقرشده به آن متصل نشده‌اند.
- برای فعال‌شدن، سرور اصلی باید با PostgreSQL بالا بیاید تا migration اجرا شود. صرف ثبت commit در GitHub به معنی deploy شدن سرور نیست.
